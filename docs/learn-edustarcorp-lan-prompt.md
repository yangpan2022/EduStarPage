# 提示词：IB 题库站点接入局域网访问（learn.edustarcorp.com）

> **版本 v2.1** —— 适用范围：**纯静态站点 + 仅局域网访问**（已按"题库是静态 JSON + 图片、没有后端服务"重写；v1 中"任务必须由服务端配合"的要求已全部删除）。
> v2.1 变更：① 新增 Chrome/Edge Local Network Access 权限说明与「手动按钮保底」；② DNS-01 必须写到公网权威 DNS，且应自动续期；③ 新增「以站点根目录发布的静态包」要求；④ 验收改用 DNS 查询而非 `ping`。
> **交付对象**：题库站点（新网页）的负责人，或其 AI agent。请完整读完再动手。
> **提供方**：EduStar 官网（edustarcorp.com）一侧，本文档用于双方对接。

---

## 0. 一句话目标

在**校园局域网内**，任何人用浏览器打开 `https://learn.edustarcorp.com` 就能看到题库；**不在局域网内**的人，从官网点进来会看到一页中英双语的明确提示，而不是浏览器自带的"无法访问此网站"。

## 1. 背景：现状与分工

1. 题库站点是**纯前端静态站**：内容以 **JSON + 图片**的形式保存，**没有后端服务、没有数据库、没有账号系统**。
2. 但它**不上公网**：`learn.edustarcorp.com` **只在局域网内解析**（内网 DNS 记录），公网 DNS **不添加任何记录**。
3. 因此外网用户**根本连不到它**，浏览器的错误页也无法由你自定义。**"非局域网提示"由官网侧负责**，题库站点不需要实现任何提示页。
4. 官网页是 HTTPS，浏览器禁止 HTTPS 页面探测 `http://` 地址（混合内容拦截）。所以有一条硬约束：

   > **题库站点必须提供 HTTPS 访问，并使用浏览器信任的证书。**
   > 这不是偏好问题，而是"官网能不能自动判断你在不在内网"的前提。

5. 好消息：拿可信证书与"只在局域网解析"**不冲突**。用 ACME 的 **DNS-01** 方式签发只需要临时加一条 TXT 记录，**不需要公网 A 记录**。

## 2. 已确定、请勿更改的边界

| 项目 | 确定值 |
| --- | --- |
| 站点形态 | **纯静态**（HTML/CSS/JS + JSON + 图片）。**不加后端** |
| 域名 | `learn.edustarcorp.com` |
| DNS | **仅局域网内解析**；公网不添加 A/CNAME 记录 |
| 协议 | **HTTPS**，浏览器信任的证书 |
| 访问控制 | **不做**登录、密码、账号。"能进内网"即权限 |
| 公网发布 | **不做**。不要在路由器上做端口映射 |
| 非局域网提示 | 由官网 edustarcorp.com 探测后显示，题库站点无需实现 |

> ⚠️ 因为站点是纯静态的，**任何能访问到该地址的人都能直接下载全部 JSON 和图片**。在"仅局域网"的前提下这是我们接受的：内网可达性就是权限边界。**请不要用前端登录/密码来"保护"题库**——纯前端做不到，只会增加复杂度。（将来若真要上公网，必须改成服务端校验，那是另一件事。）

## 3. 题库站点需要完成的事

### 3.1 网络与域名（必须）

- 在内网一台**常开**的机器上提供静态文件服务（内网服务器 / NAS / 反向代理 / 小主机都可以）。
- 监听 **443（HTTPS）**，并接受 `Host: learn.edustarcorp.com`。
- 在**内网 DNS**（路由器或内网 DNS 服务器）上把 `learn.edustarcorp.com` 解析到该机器的**内网 IP**；**不要**在公网 DNS 上加记录。
- 建议 80 端口同时监听并 301 到 HTTPS（或在网关层处理）。

### 3.2 HTTPS 证书（必须，硬性要求）

- 必须是**浏览器信任的证书**（Let's Encrypt 等公共 CA）。官网探测一个证书不被信任的 HTTPS 地址会直接失败，自动跳转永远不会生效。
- 推荐 **Let's Encrypt + DNS-01 验证**：只需临时加一条 TXT 记录，**不需要公网 A 记录**，站点不会暴露到公网。
  - ⚠️ "不需要公网 A 记录"**不等于**"不需要公网 DNS"：签证书时 CA 必须能从公网查到 `_acme-challenge.learn.edustarcorp.com` 的 TXT 记录，所以这条 TXT 要写在**公网权威 DNS** 上（只写内网 DNS 无效）。这条 TXT 是一次性的，签完即可删除。
  - ⚠️ **不要人工每 90 天续一次**。请让 DNS 服务商支持 API，用 acme.sh / certbot 的 DNS 插件自动续期；DNS API 凭据只保存在服务器上并限制权限。若确实无法自动化，请在回复中说明，官网侧需要知道这个限制。
- 如果用内网自建 CA 的自签证书，必须把根证书安装到**每一台**要访问的设备上（包括学生自带的手机、平板），否则对这些设备自动跳转必然失败。**不推荐**。
- 证书的 CN / SAN 必须包含 `learn.edustarcorp.com`。

### 3.3 站点内容（必须）

- 根路径 `/` 直接返回题库首页。
- **不要**在根路径放登录页或密码墙（我们不做访问控制）。
- 所有资源引用一律用**相对路径**（`./data/…`、`./images/…`）；页面里不要出现 `localhost`、`127.0.0.1`、内网 IP 或写死的 `http://` 地址，否则手机访问会整页样式/脚本加载失败。
- 不要做任何会跳出本站的自动重定向（例如跳到内网 IP、跳到 http）。
- 静态资源必须能通过 `https://learn.edustarcorp.com/任意路径` 直接取到。
- 建议加一个 `robots.txt`，内容为 `User-agent: *` + `Disallow: /`（万一 DNS 被误配到公网，也不会被搜索引擎收录）。
- **必须准备好一个"以站点根目录发布"的静态包。** 根目录下要直接有 `index.html`（题库首页）、`_lan_probe.png`、`robots.txt`，以及题库自己的 `data/`、`images/` 等目录。
  - ⚠️ 现在的题库预览多半放在子目录里（例如 `preview/index.html`），并且资源写成 `../chemistry/…` 这类**上一级相对路径**。这种结构**不能**直接搬到根目录，否则图片、脚本、JSON 会整片 404。请把预览目录整体提升为根目录发布包，并**逐个核对** HTML/CSS/JS/JSON 里引用的每一条路径。
  - ⚠️ **不要把内部的"V2 review 预览页"直接当学生首页。** 它通常包含原题与评分方案对照、来源资料、内部 QA 说明。发布给学生看的应该是另一套页面 + 一份经过筛选的数据包，并且要明确：哪些题目 JSON、图片和答案解析，会对"能进内网的人"直接可下载（在仅局域网前提下这是接受的，但要有意识地决定）。

### 3.4 让官网能探测到（必须，但非常简单）

官网需要一个**固定路径下的静态图片**来判断"能不能连通"：

- 在站点根目录放一个 **1×1 像素的透明 PNG**，路径固定为：

  ```
  https://learn.edustarcorp.com/_lan_probe.png
  ```

- 文件内容随意（1×1 透明 PNG 即可）。**不需要任何特殊响应头、不需要后端、不需要 CORS 配置、不需要处理 OPTIONS。**
- 只要这个文件能被浏览器以**图片**形式成功加载，官网就认为"访问者在局域网内"，随后自动跳转到 `https://learn.edustarcorp.com/`。

> **为什么用图片而不是 JSON 接口**：官网页面是 HTTPS 的，用 `<img>` 加载图片不受跨域限制、也不需要你配置任何响应头；而被运营商 DNS 劫持返回的广告页、门户页是 HTML，无法被解码成图片，天然避免误判。这是纯静态站点下最省事、最可靠的方案。

> ⚠️ **新版 Chrome / Edge 的 Local Network Access（LNA）权限**：从 Chrome 142 起，公网页面请求私有网络地址（**包括加载图片这类子资源**）可能弹出「是否允许访问本地网络」的询问。用户点「拒绝」、或询问还没被处理时，这一次探测就会失败，官网会把校内用户误判成校外。
> - 这是**浏览器行为**，题库站点无法绕过，也**不需要**为此改任何东西。
> - 兜底办法在官网侧：入口页同时保留一个**「进入题库」按钮**。用户点击触发的顶层导航（`main-frame navigation`）不受 LNA 子资源限制，**按钮 100% 可用**；自动探测只是"少点一下"的便利。
> - 请把这一情形列入正式验收（见第 6 节第 5、6 条），并在 **Chrome、Edge 和手机**上各测一次。

**（可选）** 如果你的托管平台支持自定义响应头，也可以额外交付一个 JSON 端点，供以后需要更严格判断时使用：

- `GET https://learn.edustarcorp.com/_lan_probe` → `200`，`Content-Type: application/json`，响应体 `{"ok":true}`
- 响应头需包含：
  - `Access-Control-Allow-Origin: https://edustarcorp.com`
  - `Access-Control-Allow-Private-Network: true`
  - `Cache-Control: no-store`
- `OPTIONS` 同路径 → `204`，并带上述响应头。

> nginx / Caddy / Cloudflare Pages 的 `_headers` / Netlify 的 `_headers` / Vercel 的 `vercel.json` 都能加这些响应头；**GitHub Pages 不支持自定义响应头**，所以这一项是**可选**的，不做也不影响使用。

### 3.5 运维（建议）

- 机器使用**固定内网 IP**（在路由器上做 DHCP 保留）。
- 端口在主机/路由器防火墙上放行，同一 Wi-Fi 下所有设备可访问。
- 配置**开机自启**（systemd / pm2 / Docker `restart: always` / 计划任务等），断电重启后自动恢复。
- 证书续期方式写进运维说明（DNS-01 可自动化；手动续期则每 90 天一次）。

## 6. 验收清单（请逐条回复结果）

1. 用**内网 DNS 查询**确认真实解析结果（**不要用 `ping`**——ICMP 常被防火墙挡住，`ping` 不通不代表 DNS 没解析）：
   - 校内设备：`nslookup learn.edustarcorp.com` / `dig learn.edustarcorp.com` → 返回**内网 IP**；
   - 手机切 4G/5G 后同样查询 → **解析失败 / 无记录**（证明公网没有 A/CNAME）。
2. 内网浏览器打开 `https://learn.edustarcorp.com/` → 正常显示题库，地址栏**无证书警告**，F12 Console **无混合内容报错、无 404 资源**（这条同时验证"根目录发布包 + 相对路径"是否真的都通）。
3. 浏览器打开 `https://learn.edustarcorp.com/_lan_probe.png` → 显示为一张（透明）图片，**不是 HTML 页**。
4. 同一局域网内打开 `https://edustarcorp.com/questionbank/ib/` → 自动跳转到题库。
5. **手动按钮验证**：在 **Chrome、Edge 和手机**上各试一次，点「进入题库」按钮 → 一定能打开题库（这条不依赖探测，必须 100% 成功）。
6. **LNA 权限验证（正式验收项）**：在 Chrome 上打开官网入口页，如果出现「是否允许访问本地网络」的询问：
   - 点**允许** → 应自动跳转；
   - 点**拒绝** → 自动跳转失败，但页面仍显示提示，**点「进入题库」按钮仍能进入**。
7. 手机切到 4G/5G 打开同一个官网页面 → 显示中英双语「仅限校园内网访问」提示（而不是浏览器报错页）。
8. 用内网 IP 直连 `https://<内网IP>/` → 返回「请通过官网入口进入」之类的静态页或 404（可选，用于避免被随意扫到）。
9. 重启服务器 → 服务自动恢复。
10. `https://learn.edustarcorp.com/robots.txt` → 返回 `Disallow: /`。
11. 证书到期时间与续期方式已写入运维说明，并确认续期是**自动**的。

## 附录 A：官网侧会做什么（你们**不需要**实现，仅供对齐）

- 官网是 Next.js 静态导出站点（`output: "export"`，无服务端），入口页为 `/questionbank/ib/`：
  1. 进入页面后立即在后台用 `<img>` 加载 `https://learn.edustarcorp.com/_lan_probe.png?_=<时间戳>`，约 2000 ms 超时；
  2. **加载成功** → `location.replace("https://learn.edustarcorp.com/")`，访问者直接进入题库；
  3. **加载失败 / 超时** → 停留在页面上，显示中英双语的「仅限校园内网访问」提示与排查步骤（连接校园 Wi-Fi、点按钮进入、仍然打不开的原因）。
- 该页面**同时提供一个「进入题库」按钮**（顶层导航到 `https://learn.edustarcorp.com/`）。这是保底路径：Chrome 的 LNA 权限询问只会拦自动探测，不会拦用户点击的顶层导航。
- 排查步骤会提示一种常见原因：Chrome / Edge 新版对"网页访问本地网络"会弹出**权限询问**，若点了「拒绝」，探测会失败——此时允许后刷新即可，或者直接点按钮。
- 由于双方都是纯静态站点，判断只能在浏览器端完成，所以 **3.2 的证书是整条链路的关键**。
- 微信内置浏览器对本地网络访问支持很差，入口页会提示用户「在右上角选择"在浏览器中打开"」。

## 附录 B：拿不到浏览器信任的证书怎么办（降级方案，体验会明显变差）

- 官网入口从"探测 + 自动跳转"退化为**普通超链接**（`<a href="https://learn.edustarcorp.com/">`）。顶层导航不受跨域与混合内容限制，仍然能跳转。
- 代价：**没有任何条件判断**。不在内网的人点了只会看到浏览器自带的「无法访问此网站」，官网侧最多只能常驻显示一条「仅限校园内网访问」的提示。
- 另一种思路是把入口页放到 http 来源上（需在 Hostinger 关闭强制 HTTPS），复杂度和维护成本都更高，一般不值得。
- 结论：**务必先把 3.2 的证书方案做出来**，这是整个体验的关键。
