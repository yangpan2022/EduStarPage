# 提示词：把学习平台接入 learn.edustarcorp.com（局域网专用）

> **交付对象**：学习平台（新网页）的负责人，或其 AI agent。请完整读完再动手。
> **提供方**：EduStar 官网（edustarcorp.com）一侧，用于双方对接。
> 本提示词假定"教室网页"就是 edustarcorp.com 官网。若入口其实在另一个站点，第 3、4 节的契约不变，只是入口页要放到那个站点上。

---

## 0. 一句话目标

教室里的人从官网点一下就能进入学习平台；**不在教室内网的人**看到一句明确的中英提示，而不是一个"网页打不开"的浏览器错误页。

## 1. 背景：为什么必须这样做

1. 学习平台**不上公网**，只在内网提供服务。
2. `learn.edustarcorp.com` **只在局域网内解析**（内网 DNS 或各机器 hosts），公网 DNS **不添加 A 记录**。
3. 因此外网用户**根本连不到**平台，浏览器的错误页也无法由你们自定义。**"非内网提示"由官网侧负责**：官网页在浏览器里探测平台是否可达——可达就自动跳转，不可达就显示提示（中英双语）。你们不需要做提示页。
4. 但这个探测有一条硬约束：**官网是 HTTPS，浏览器禁止 HTTPS 页面探测 `http://` 地址**（混合内容拦截：`fetch`/XHR 被直接拒绝，`<img>` 也会被强制升级为 https 再失败）。所以：

   > **学习平台必须提供 HTTPS 访问，并使用浏览器信任的证书。**
   > 这不是偏好问题，而是"能不能自动判断内网"的前提。

5. 好消息：拿可信证书和"只在局域网解析"**不冲突**。用 ACME 的 **DNS-01** 方式签发只需要一条临时 TXT 记录，**不需要公网 A 记录**，平台不会因此暴露到公网。

## 2. 已确定的方案（请勿偏离）

| 项目 | 确定值 |
| --- | --- |
| 域名 | `learn.edustarcorp.com` |
| DNS | 仅局域网内解析（内网 DNS 记录，或各机器 hosts）；公网不可解析 |
| 协议 | **HTTPS**，浏览器信任的证书 |
| 入口 | 由官网（edustarcorp.com）跳转进入 |
| 非内网提示 | 由官网侧探测后显示，你们不需要实现 |
| 访问控制 | 无账号、无口令；"能进内网"即权限 |
| 公网暴露 | 完全不需要，也不要开放端口到公网 |

## 3. 你们需要完成的改造

### 3.1 监听与域名

- 服务必须监听 **`0.0.0.0`**（不是 `127.0.0.1`），端口固定，建议直接 **443**（若用 8443，URL 会带端口，探测与跳转都要跟着改，不推荐）。
- 必须接受 `Host: learn.edustarcorp.com` 的请求，并能按该域名提供正确内容。
- **所有静态资源使用相对路径**（`/assets/...`），绝对不要写 `localhost`、`127.0.0.1` 或固定内网 IP——否则手机访问会整页样式/脚本加载失败。
- 不要在任何资源里使用 `http://` 绝对地址（会触发混合内容，页面会崩）。
- 不要对 `learn.edustarcorp.com` 做 http→https 之外的域名跳转（尤其不要跳到某个固定 IP）。

### 3.2 探测端点（本次交付的核心）

请实现两个**无需登录、无 cookie、无鉴权**即可访问的端点：

**① `GET /_lan_probe`（主探测）**

- 返回 `200`，`Content-Type: application/json`，响应体例如 `{"ok":true,"service":"learn"}`
- 必须带以下响应头：
  - `Access-Control-Allow-Origin: https://edustarcorp.com`（如需同时支持 www，则按 Origin 回显或加 `https://www.edustarcorp.com`；允许用 `*`，因为不带凭据）
  - `Access-Control-Allow-Private-Network: true`（应对 Chrome 的 Private Network Access 预检）
  - `Cache-Control: no-store`
- 必须正确处理预检：`OPTIONS /_lan_probe` → `204`，并带上面这些头
- 不要重定向、不要要求证书以外的鉴权、不要依赖 Host 之外的会话

**② `GET /_lan_probe.png`（不依赖 CORS 的兜底探测）**

- 返回一张 1×1 透明 PNG，`Cache-Control: no-store`

这两个端点也顺便当作健康检查端点使用（运维监控可复用）。

### 3.3 Host 校验与兜底

- 当 `Host` 不是 `learn.edustarcorp.com`（例如有人用内网 IP 直连）时，返回一个静态提示页：**「请通过 EduStar 官网的入口进入本平台」**，或直接 403/404。避免平台被随意扫到。
- 可选：在页面顶部加一条不显眼的提示「仅限教室内网访问」。

### 3.4 HTTPS 证书（关键项）

- **首选**：Let's Encrypt + **DNS-01** 验证（用 edustarcorp.com 的 DNS 服务商 API 自动加 TXT，或经授权后手动添加）。**不需要公网 A 记录**，与"仅内网解析"完全兼容。
  - 自动续期：certbot + DNS 插件（Cloudflare / Hostinger DNS API 等）。若只能手动续期，请把"每 90 天续一次"写进运维说明。
- **不推荐**：内网自签 CA（mkcert 等）。每台访问设备都要安装根证书，手机和访客设备会非常痛苦。
- **不接受**：只有 http；或自签证书但设备未安装根证书。这两种情况官网侧无法自动判断，只能退化成静态提示（见附录 B）。

### 3.5 运维

- 服务器使用**固定内网 IP**（在路由器上做 DHCP 保留）。
- 端口在路由器/主机防火墙放行，同一 Wi-Fi 下所有设备可访问。
- 配置**开机自启**（systemd / pm2 / Docker `restart: always` 等），断电重启后自动恢复。

## 4. 与官网的接口契约（双方按此实现，不要自行更改）

| 项目 | 约定 |
| --- | --- |
| 入口 URL | `https://learn.edustarcorp.com/` |
| 探测 URL | `https://learn.edustarcorp.com/_lan_probe`（兜底：`https://learn.edustarcorp.com/_lan_probe.png`） |
| 请求方法 | `GET`，无查询参数，`credentials: 'omit'`，`cache: 'no-store'` |
| 期望响应 | 2xx；带 `Access-Control-Allow-Origin`（覆盖 `https://edustarcorp.com`）与 `Access-Control-Allow-Private-Network: true` |
| 官网侧超时 | **2000 ms** |
| 官网侧判定 | 请求成功（2xx）→ 视为在教室内网 → 跳转到入口 URL；请求失败/超时/被浏览器拦截 → 视为不在内网 → 显示中英双语提示 |
| 官网侧不发送任何凭据 | 也不要尝试从响应体里读业务数据，只看成败 |

> 若你们需要把入口做在子路径（例如 `/login`、`/lms`），请在回复时明确，官网侧跳转目标会同步修改。

## 5. 明确**不需要**做的事

- 不申请公网 A 记录、不把端口映射到公网、不接 CDN
- 不做 SEO、不接统计、不需要被搜索引擎收录
- 不需要账号/密码体系（内网即权限）
- **不需要**为外网用户做兜底提示页（这部分由官网侧实现）
- 不需要适配微信内置浏览器（我们会引导用户"用浏览器打开"，见附录 A）

## 6. 验收清单（请逐条回复结果）

1. 内网设备访问 `https://learn.edustarcorp.com/` → 正常打开，地址栏**无证书警告**，F12 Console **无混合内容报错**、无 404 资源。
2. 浏览器直接打开 `https://learn.edustarcorp.com/_lan_probe` → 返回 JSON，响应头含 CORS 相关两项。
3. `curl -I https://learn.edustarcorp.com/_lan_probe` 与 `curl -X OPTIONS` → 返回预期状态码与响应头（请把输出贴回来）。
4. 手机（同一 Wi-Fi）访问入口 URL → 正常显示。
5. 用内网 IP 直连 `https://<内网IP>/` → 显示「请通过官网入口进入」或 404。
6. 设备切到 4G / 手机热点后访问 `learn.edustarcorp.com` → **打不开（DNS 解析失败）属预期**；此时官网页应显示提示（这一条由官网侧验收）。
7. 重启服务器 → 服务自动恢复。
8. 证书到期时间与续期方式写入运维说明。

## 7. 请回复给官网侧的信息

- 固定内网 IP 与端口、最终协议（https/http）
- 证书是否已就绪、签发与续期方式
- 探测端点上线后的实际响应头（`curl -i` 输出）
- 平台入口的实际路径（`/` 还是 `/login` 等）
- 技术栈与运行方式（便于后续联合排查）

## 附录 A：官网侧会做什么（你们**不需要**实现，仅供对齐）

- 在官网（Next.js 静态导出，无服务端）新增入口页 `/classroom/`，浏览器端执行：
  1. 加载后立即 `fetch(PROBE_URL, { mode: 'cors', credentials: 'omit', cache: 'no-store', signal: 2000ms })`
  2. 成功 → `location.replace('https://learn.edustarcorp.com/')`
  3. 失败 → 显示中英双语文案：「你当前不在教室内网 / 此学习平台仅限校内网络访问」，并给出排查步骤 + 重试按钮
- 排查步骤会提示两种常见原因：**没连教室 Wi-Fi**，以及**在浏览器弹出的"访问本地网络"权限中点了拒绝**（Chrome 新版对此类探测会询问权限，允许后即可跳转）。
- 由于是纯静态站点，判断只能在浏览器端完成——所以你们那边的 CORS 与 HTTPS 配置必须严格按第 4 节执行。
- 微信内置浏览器对本地网络访问支持很差，入口页会提示用户「在右上角选择"在浏览器中打开"」。

## 附录 B：如果拿不到可信证书（降级方案，体验会明显变差）

- 平台只提供 http，官网入口改为普通超链接直接跳 `http://learn.edustarcorp.com/`（顶层导航不受混合内容限制，仍可跳转）。
- 代价：**没有任何条件判断**。不在内网的人点了只会看到浏览器自带的「无法访问此网站」；官网侧只能常驻显示一条「仅限教室内网访问」的提示。
- 另一种思路是把探测页放在 http 来源上（官网需保留 http 入口，Hostinger 上要关闭强制 HTTPS），复杂度和维护成本都更高，一般不值得。
- 结论：**优先把 3.4 的证书方案做出来**，这是整个体验的关键。
